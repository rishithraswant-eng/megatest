================================================================================
DATABASE SCHEMA - LOCAL, ON-DEVICE (SQLite) - REV. 2
AI Incident Report Assistant
Updated to support: department/incident-type form routing, draft sessions
distinct from submitted incidents, field-level provenance/evidence/status,
correction history, concurrency via session/turn/draft-revision stamps,
admin auth/roles, and schema/model versioning with rollback. GNN/causal
tables are retained but explicitly marked optional/future.
================================================================================

NOTES
--------------------------------------------------------------------------------
- Single SQLite file stored on-device, e.g. /data/incident_assistant.db
- No remote database, no sync service. All reads/writes are local.
- Timestamps stored as ISO-8601 strings (UTC) unless noted.
- IDs are TEXT UUIDs unless noted otherwise.
- Model confidence values are stored for routing/UX use only -- never
  treated or presented as calibrated probabilities (see 01_IDEA_OVERVIEW.txt
  section 8).

--------------------------------------------------------------------------------
TABLE: organizations
--------------------------------------------------------------------------------
  org_id          TEXT PRIMARY KEY
  name            TEXT NOT NULL
  created_at      TEXT NOT NULL
  floorplan_path  TEXT NOT NULL
  floorplan_w_px  INTEGER NOT NULL
  floorplan_h_px  INTEGER NOT NULL

--------------------------------------------------------------------------------
TABLE: zones
--------------------------------------------------------------------------------
  zone_id         TEXT PRIMARY KEY
  org_id          TEXT NOT NULL REFERENCES organizations(org_id)
  name            TEXT NOT NULL
  floor           TEXT
  polygon_json    TEXT NOT NULL
  category_hints  TEXT             -- JSON array of incident_type labels likely here
  created_at      TEXT NOT NULL

--------------------------------------------------------------------------------
TABLE: departments  (NEW)
--------------------------------------------------------------------------------
Purpose: the responsible teams incidents route to (Facilities/Electrical,
IT, Security, ...). Each department owns a queue of incidents.

  department_id   TEXT PRIMARY KEY
  org_id          TEXT NOT NULL REFERENCES organizations(org_id)
  name            TEXT NOT NULL
  description     TEXT

--------------------------------------------------------------------------------
TABLE: incident_types  (NEW -- replaces the old flat `categories` table)
--------------------------------------------------------------------------------
Purpose: one row per incident type (water leak, electrical hazard,
access-control fault, ...). This is the routing+form definition the app
loads once the type is identified. Several incident types may point to the
same department.

  incident_type_id   TEXT PRIMARY KEY
  org_id              TEXT NOT NULL REFERENCES organizations(org_id)
  label               TEXT NOT NULL        -- "Water Leak"
  department_id       TEXT NOT NULL REFERENCES departments(department_id)
  default_priority    TEXT NOT NULL        -- "Low" | "Medium" | "High"
  responsible_roles   TEXT                 -- JSON array of role names
  disambiguation_hint TEXT                 -- short text used when this type
                                            -- is ambiguous against another

--------------------------------------------------------------------------------
TABLE: form_fields  (NEW)
--------------------------------------------------------------------------------
Purpose: the actual form schema per incident type -- which fields exist,
whether each is required or optional/clarifying, and its data type. This
table IS the "department-specific form," read by application code, not
hard-coded per type in app logic.

  field_id          TEXT PRIMARY KEY
  incident_type_id  TEXT NOT NULL REFERENCES incident_types(incident_type_id)
  field_name         TEXT NOT NULL         -- "zone" | "time" | "leak_source" | ...
  field_kind         TEXT NOT NULL         -- "required" | "clarifying"
  data_type          TEXT NOT NULL         -- "text" | "enum" | "datetime" | "boolean"
  enum_values_json   TEXT                  -- if data_type = "enum"
  prompt_template    TEXT NOT NULL         -- cached question text for TTS/UI
  display_order      INTEGER NOT NULL

--------------------------------------------------------------------------------
TABLE: users
--------------------------------------------------------------------------------
  user_id         TEXT PRIMARY KEY
  org_id          TEXT NOT NULL REFERENCES organizations(org_id)
  display_name    TEXT NOT NULL
  role            TEXT NOT NULL            -- "employee" | "admin"
  home_zone_id    TEXT REFERENCES zones(zone_id)
  preferred_lang  TEXT DEFAULT 'auto'      -- "en" | "hi" | "auto"

--------------------------------------------------------------------------------
TABLE: admin_credentials  (NEW)
--------------------------------------------------------------------------------
Purpose: local admin authentication/roles -- required by the reliability
section of 01_IDEA_OVERVIEW.txt (admin auth/roles is a stated requirement,
not optional polish).

  admin_id        TEXT PRIMARY KEY
  user_id         TEXT NOT NULL REFERENCES users(user_id)
  password_hash   TEXT NOT NULL
  role_level      TEXT NOT NULL            -- "facilities_admin" | "department_admin" | "super_admin"
  created_at      TEXT NOT NULL

--------------------------------------------------------------------------------
TABLE: draft_sessions  (NEW)
--------------------------------------------------------------------------------
Purpose: owns the conversation BEFORE a submitted incident exists. A
crashed/abandoned conversation stays a draft, never becomes a phantom
incident row. Supports draft recovery after a crash/interruption.

  session_id        TEXT PRIMARY KEY
  org_id            TEXT NOT NULL REFERENCES organizations(org_id)
  reporter_user_id  TEXT NOT NULL REFERENCES users(user_id)
  started_at        TEXT NOT NULL
  last_active_at    TEXT NOT NULL
  current_revision  INTEGER NOT NULL DEFAULT 0   -- bumped on every correction
  state             TEXT NOT NULL            -- matches state machine in
                                              -- 04_DESIGN_FLOW.txt: "LISTENING"|
                                              -- "CLASSIFYING"|"DISAMBIGUATING"|
                                              -- "FORM_FILLING"|"CLARIFYING"|
                                              -- "REVIEWING"|"SUBMITTED"|"CANCELLED"|
                                              -- "ABANDONED"
  proposed_incident_type_id  TEXT REFERENCES incident_types(incident_type_id)
  linked_group_id   TEXT                    -- shared across incidents spawned
                                             -- from one narration; NULL if single

--------------------------------------------------------------------------------
TABLE: dialogue_turns
--------------------------------------------------------------------------------
Purpose: full transcript of the conversation. Carries the concurrency
stamps required by 03_TRD.txt (session/turn/draft-revision) so a stale
model result can never overwrite a newer correction.

  turn_id           TEXT PRIMARY KEY
  session_id        TEXT NOT NULL REFERENCES draft_sessions(session_id)
  turn_index        INTEGER NOT NULL
  draft_revision    INTEGER NOT NULL        -- draft_sessions.current_revision
                                             -- at the time this turn was processed
  speaker           TEXT NOT NULL           -- "user" | "assistant"
  stage             TEXT NOT NULL           -- "SPEAK"|"IDENTIFY"|"FORM_FILLING"|
                                             -- "CLARIFYING"|"REVIEW"
  raw_text          TEXT NOT NULL
  is_final          INTEGER NOT NULL DEFAULT 0   -- streaming ASR: 0=tentative,1=final
  normalized_text   TEXT                    -- English-normalized, where applicable
  lang_detected     TEXT                    -- "en" | "hi" | "mixed"
  dialogue_act      TEXT                    -- "answer"|"correction"|"negation"|
                                             -- "uncertainty"|"confirmation"|NULL
  timestamp         TEXT NOT NULL

--------------------------------------------------------------------------------
TABLE: extracted_fields  (REPLACES `extracted_slots` -- now field-level,
                          with explicit status/provenance/evidence)
--------------------------------------------------------------------------------
Purpose: the live form-filling state for one draft session. One row per
field per revision, so correction history is a true history, not an
overwrite.

  field_row_id      TEXT PRIMARY KEY
  session_id        TEXT NOT NULL REFERENCES draft_sessions(session_id)
  field_id          TEXT NOT NULL REFERENCES form_fields(field_id)
  draft_revision    INTEGER NOT NULL
  value             TEXT                    -- NULL if status is "missing"/"unknown"
  status            TEXT NOT NULL           -- "missing"|"known"|"unknown"|"ambiguous"
  provenance        TEXT NOT NULL           -- "lnn"|"llm"|"user_direct"
  confidence        REAL                    -- NOT a calibrated probability; UX/routing only
  evidence_turn_id  TEXT REFERENCES dialogue_turns(turn_id)   -- transcript span backing this value
  superseded        INTEGER NOT NULL DEFAULT 0   -- 1 once a later revision replaces it

--------------------------------------------------------------------------------
TABLE: correction_history  (NEW)
--------------------------------------------------------------------------------
Purpose: explicit audit trail of corrections, and which derived predictions
they invalidated (e.g. a corrected description invalidating a stored
severity classification).

  correction_id       TEXT PRIMARY KEY
  session_id          TEXT NOT NULL REFERENCES draft_sessions(session_id)
  field_row_id_before TEXT NOT NULL REFERENCES extracted_fields(field_row_id)
  field_row_id_after  TEXT NOT NULL REFERENCES extracted_fields(field_row_id)
  invalidated_json    TEXT                  -- JSON list of other field_row_ids
                                             -- invalidated by this correction
  corrected_at        TEXT NOT NULL
  triggering_turn_id  TEXT NOT NULL REFERENCES dialogue_turns(turn_id)

--------------------------------------------------------------------------------
TABLE: incidents
--------------------------------------------------------------------------------
Purpose: the final, submitted, structured record. Created only at SUBMIT,
from a draft_session's confirmed revision -- never built up in place.

  incident_id        TEXT PRIMARY KEY
  org_id             TEXT NOT NULL REFERENCES organizations(org_id)
  session_id         TEXT NOT NULL REFERENCES draft_sessions(session_id)
  reporter_user_id   TEXT NOT NULL REFERENCES users(user_id)
  zone_id            TEXT NOT NULL REFERENCES zones(zone_id)
  incident_type_id   TEXT NOT NULL REFERENCES incident_types(incident_type_id)
  department_id      TEXT NOT NULL REFERENCES departments(department_id)
  linked_group_id    TEXT                   -- see draft_sessions; groups
                                             -- incidents from one narration
  description_en     TEXT NOT NULL
  original_lang      TEXT NOT NULL          -- "en" | "hi" | "mixed"
  reported_at         TEXT NOT NULL
  incident_time       TEXT
  priority            TEXT NOT NULL         -- "Low" | "Medium" | "High"
  status               TEXT NOT NULL DEFAULT 'Open'  -- "Open"|"In Progress"|"Resolved"
  confirmed_revision   INTEGER NOT NULL     -- which draft_revision was confirmed
  local_submission_only INTEGER NOT NULL DEFAULT 1
                                             -- 1 = saved locally, no delivery
                                             -- mechanism confirmed yet; app code
                                             -- must not claim "sent" until a real
                                             -- delivery mechanism flips this

--------------------------------------------------------------------------------
TABLE: function_calls
--------------------------------------------------------------------------------
Purpose: log of every local function call the semantic model made. All
functions are drawn from a fixed, typed, allowlisted set -- the model
cannot invoke anything outside this table's known function_name values.

  call_id         TEXT PRIMARY KEY
  session_id      TEXT NOT NULL REFERENCES draft_sessions(session_id)
  function_name   TEXT NOT NULL            -- see 03_TRD.txt section 5 for the allowlist
  arguments_json  TEXT NOT NULL
  result_json     TEXT NOT NULL
  called_at       TEXT NOT NULL

--------------------------------------------------------------------------------
TABLE: schema_versions / model_versions  (NEW)
--------------------------------------------------------------------------------
Purpose: versioning and rollback for form schemas, routing rules, and model
weights, as required by the reliability section.

  version_id      TEXT PRIMARY KEY
  artifact_type   TEXT NOT NULL            -- "form_schema"|"routing_rules"|
                                            -- "asr_model"|"lnn_model"|"llm_model"|"tts_model"
  artifact_name   TEXT NOT NULL
  version_label   TEXT NOT NULL
  is_active       INTEGER NOT NULL DEFAULT 0
  released_at     TEXT NOT NULL
  rollback_of     TEXT REFERENCES schema_versions(version_id)   -- NULL unless this
                                                                 -- version is a rollback

--------------------------------------------------------------------------------
TABLE: incident_relations  (GNN output -- OPTIONAL / FUTURE, see note)
--------------------------------------------------------------------------------
  relation_id        TEXT PRIMARY KEY
  incident_id_a      TEXT NOT NULL REFERENCES incidents(incident_id)
  incident_id_b       TEXT NOT NULL REFERENCES incidents(incident_id)
  relation_score      REAL NOT NULL
  relation_reason      TEXT
  computed_at           TEXT NOT NULL

--------------------------------------------------------------------------------
TABLE: causal_edges  (OPTIONAL / FUTURE, see note)
--------------------------------------------------------------------------------
  edge_id         TEXT PRIMARY KEY
  org_id          TEXT NOT NULL REFERENCES organizations(org_id)
  cause_factor    TEXT NOT NULL
  effect_incident_type_id TEXT NOT NULL REFERENCES incident_types(incident_type_id)
  weight          REAL NOT NULL
  lag_hint        TEXT
  computed_at     TEXT NOT NULL

NOTE ON incident_relations / causal_edges: per 01_IDEA_OVERVIEW.txt section
9, these are NOT a committed part of the core build. They exist in the
schema so Phase 4 can prototype them without a later migration, but nothing
in Phases 1-3/5 may depend on them being populated, and the UI must never
present their output as a verified cause.

--------------------------------------------------------------------------------
INDEXES (minimum set)
--------------------------------------------------------------------------------
  CREATE INDEX idx_incidents_zone        ON incidents(zone_id);
  CREATE INDEX idx_incidents_dept        ON incidents(department_id, status);
  CREATE INDEX idx_incidents_reported    ON incidents(reported_at);
  CREATE INDEX idx_dialogue_session      ON dialogue_turns(session_id, turn_index);
  CREATE INDEX idx_fields_session_rev    ON extracted_fields(session_id, draft_revision);
  CREATE INDEX idx_relations_a           ON incident_relations(incident_id_a);
  CREATE INDEX idx_relations_b           ON incident_relations(incident_id_b);

--------------------------------------------------------------------------------
WHY THIS SHAPE CHANGED FROM REV. 1
--------------------------------------------------------------------------------
  - `incident_types` + `form_fields` replace the flat `categories` table
    because the form itself is now per-incident-type data, not a hard-coded
    branch in app logic -- this is what lets Phase 3 build the routing/form
    engine entirely against local config, with no model in the loop yet.
  - `draft_sessions` is new because the app must distinguish "someone is
    mid-conversation" from "an incident was actually submitted" -- the old
    schema had no such distinction and risked treating a crashed
    conversation as a real incident.
  - `extracted_fields` replaces `extracted_slots`: it is now a per-revision,
    per-field row (status + provenance + evidence + confidence), which is
    what correction_history needs to exist as a real audit trail rather
    than an overwrite.
  - `schema_versions`/`model_versions` and `admin_credentials` exist purely
    to satisfy the reliability requirements in 01_IDEA_OVERVIEW.txt section
    8 -- they are not optional nice-to-haves, the source idea document
    calls them out explicitly.
